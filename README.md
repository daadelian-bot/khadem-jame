# سامانه جامع خادمین مجموعة السیدة زینب سلام الله علیها

## وضعیت پروژه
- مخزن: https://github.com/daadelian-bot/khadem-jame
- شاخهٔ اصلی: `main`
- سایت: https://daadelian-bot.github.io/khadem-jame/
- ورودی سایت: `index.html` (هدایت مستقیم به نسخهٔ اصلی)
- رابط اصلی فعال: `live-data.html`
- کد برنامه: `app.js`
- تنها stylesheet فعال: `style.css`؛ پوستهٔ مرجع سرمه‌ای/طلایی با شناسهٔ انتشار `20261016-41`
- پوستهٔ آفلاین و پاک‌سازی cacheهای قدیمی: `service-worker.js`
- راهنمای ادامهٔ کار در ChatGPT و اتصال حساب‌های دیگر: [CHATGPT_HANDOFF.md](CHATGPT_HANDOFF.md)
- مشخصات بخش البسه خادمی: [ALBASE_REQUIREMENTS.md](ALBASE_REQUIREMENTS.md)
- ممیزی پیش‌انتشار و چک‌لیست پذیرش: [RELEASE_AUDIT_20261012_FA.md](RELEASE_AUDIT_20261012_FA.md)

## نکات مهم پیش از تغییر کد
- فایل `logo.png` در ریشهٔ مخزن باید حفظ شود؛ آن را حذف یا جایگزین نکنید مگر با اجازهٔ صریح کاربر.
- `live-data.html` فایل‌های فعال `app.js` و `style.css` را بارگذاری می‌کند؛ فایل‌های پوستهٔ قدیمیِ جداگانه در شاخهٔ اصلی وجود ندارند. پیش از حذف هر فایل، وابستگی‌ها را دوباره بررسی کنید.
- گزارش `RELEASE_READINESS.md` مربوط به یک بازبینی قدیمی نسخهٔ ۱۰۴ است و نباید به‌عنوان گزارش وضعیت فعلی نسخهٔ ۱۴۲ تلقی شود.
- قبل از هر ویرایش، فایل و SHA فعلی آن را از شاخهٔ `main` بخوانید. اگر چند حساب یا نفر روی مخزن کار می‌کنند، پیش از نوشتن دوباره آخرین commit را بررسی کنید.
- بعد از commit، نتیجهٔ GitHub Actions/GitHub Pages را بررسی کنید. ثبت commit به‌تنهایی اثبات انتشار موفق نیست.
- پس از انتشار، سایت را با لینک دارای پارامتر نسخه باز کنید و عملکرد واقعی را آزمایش کنید.

## امنیت و داده‌ها
- هیچ مهاجرت SQL یا تغییر در جدول‌ها، ستون‌ها، triggerها، RLS/policyها یا داده‌های Supabase بدون توضیح دلیل و اجازهٔ صریح کاربر انجام نشود.
- دو رکوردی که `service_records.khadem_code` آن‌ها NULL است، بدون اجازهٔ صریح پر نشوند.
- هیچ داده‌ای را برای «تمیزکاری» حذف یا بازنویسی نکنید.
- کلید `service_role`، رمزها، access tokenها و اسرار سرور را در HTML یا هر فایل عمومی قرار ندهید و از کاربر نخواهید آن‌ها را در چت بفرستد.

## روش پیشنهادی انتشار
1. بررسی منبع فعلی و SHA فایل‌ها.
2. اصلاح محدود و مشخص، بدون تغییرات نامرتبط.
3. بررسی نحوی و آزمون‌های متناسب با تغییر.
4. ثبت commit با پیام روشن؛ برای تغییرات بزرگ از branch و Pull Request استفاده کنید.
5. بررسی نتیجهٔ workflow انتشار.
6. ارائهٔ SHA، فهرست فایل‌های تغییرکرده، نتیجهٔ آزمون‌ها و لینک سایت.
7. تأیید نهایی با حساب آزمایشی؛ هیچ‌گاه از روی موفقیت workflow نتیجه نگیرید که ورود یا همهٔ قابلیت‌های برنامه حتماً درست کار می‌کنند.
