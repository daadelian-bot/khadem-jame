# راه‌اندازی یک‌بارهٔ پنل توسعه هوشمند

پنل «توسعه هوشمند» برای مدیر اصلی در APK درخواست تغییرات را ثبت می‌کند. کد و کلیدهای محرمانه داخل APK قرار نمی‌گیرند.

## نیازمندی‌های یک‌باره
1. در Supabase پروژه `fxxtyfurdzpzfvweoppo`، از بخش Edge Function Secrets مقدار `GITHUB_AUTOMATION_TOKEN` را تنظیم کنید. این توکن باید متعلق به حساب `daadelian-bot` باشد و فقط مجوزهای لازم برای ساخت Issue در مخزن `daadelian-bot/khadem-jame` را داشته باشد. پنل هنگام استفاده حساب توکن را بررسی می‌کند.
2. در تنظیمات Secrets مخزن GitHub، `OPENAI_API_KEY` و `GH_AUTOMATION_TOKEN` باید موجود باشند. workflow فعلی اگر هرکدام را نداشته باشد، درخواست را اجرا نمی‌کند.
3. Edge Function با نام `submit-developer-request` باید از فایل همین مسیر منتشر شود و اعتبارسنجی JWT فعال بماند.
4. پس از ادغام تغییرات رابط، workflow ساخت APK با تغییر `live-data.html` اجرا می‌شود. artifact آن نسخهٔ آزمایشی APK است؛ انتشار امضاشدهٔ نهایی جداست.

## نحوهٔ استفاده
- با حساب فعال مدیر اصلی وارد APK شوید.
- از پیوند «توسعه هوشمند (مدیر اصلی)» استفاده کنید.
- عنوان و شرح درخواست را بنویسید و ثبت کنید.
- وضعیت درخواست و پیام‌های عامل توسعه را در همان صفحه ببینید.

## امنیت و محدودیت‌ها
- هیچ توکن GitHub، کلید OpenAI یا کلید service-role نباید در HTML، APK، localStorage یا متن درخواست قرار گیرد.
- درخواست کد به صورت تغییر پیشنهادی در شاخه جداگانه و PR پیش‌نویس آماده می‌شود؛ این نسخه هنوز ادغام/انتشار خودکار و امن از داخل APK را پیاده‌سازی نمی‌کند.
- workflow فعلی به‌طور عمدی تغییر فایل‌های workflow و Supabase را در درخواست‌های خودکار مسدود می‌کند.
- تغییرات دادهٔ زنده، نقش‌ها یا RLS بدون مسیر تأیید جداگانه نباید اجرا شوند.
- اگر secretها هنوز تنظیم نشده باشند، صفحه باید پیام روشن پیکربندی را نمایش دهد؛ از ادعای اجرای موفق خودداری کنید.
