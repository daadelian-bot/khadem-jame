# راه‌اندازی اتصال گفت‌وگو به فرایند توسعه — راهنمای فارسی

## وضعیت واقعی
این مخزن اکنون GitHub Actions برای بررسی کد و ساخت APK دارد. این موارد به‌خودی‌خود به پیام‌های یک گفت‌وگوی معمولی ChatGPT دسترسی ندارند. برای اینکه پیام به‌طور مستقیم محرک شود، باید یک ابزار/Action صریح در محیط ChatGPT یا یک واسط بیرونیِ مجاز، پیام را به endpoint اختصاصی بفرستد. تغییر فایل‌های مخزن به‌تنهایی نمی‌تواند برای این گفت‌وگو webhook بسازد یا تنظیمات حساب ChatGPT را تغییر دهد.

## معماری پیشنهادی
1. **ورودی گفت‌وگو:** یک Custom GPT/Action یا واسط مجاز، درخواست تغییر ساختاریافته را به endpoint بفرستد. در صورت نبود قابلیت Action در محیط فعلی، کاربر باید از یک واسط بیرونی استفاده کند.
2. **درگاه امن:** Supabase Edge Function یا سرویس کوچک جداگانه، درخواست را با کلید اختصاصی بررسی کند، شناسه درخواست و زمان را اعتبارسنجی کند و از replay جلوگیری کند.
3. **محدوده اجرا:** فقط مخزن `daadelian-bot/khadem-jame` و شاخه‌های کاری؛ هیچ توکن مدیریتی در کد مرورگر یا فایل عمومی قرار نگیرد.
4. **عامل تغییر کد:** یک عامل توسعه دارای دسترسی محدود، درخواست را به branch و Pull Request تبدیل کند. صرف GitHub Actions یا webhook به‌تنهایی نمی‌تواند کد را بر اساس زبان طبیعی بنویسد؛ برای این قسمت باید یک coding agent مجاز و هزینه/مجوزهای آن فراهم باشد.
5. **آزمون خودکار:** GitHub Actions آزمون‌های موجود، بررسی‌های تکمیلی، و در صورت ارتباط ساخت APK را اجرا کند.
6. **تأیید و انتشار:** تا وقتی مالک سامانه این سیاست را تغییر نداده، Pull Request پس از آزمون آماده بررسی می‌شود و انتشار نهایی منتظر تأیید مالک می‌ماند. تغییرات احراز هویت، RLS، نقش‌ها، مالی، حذف داده و schema باید بررسی امنیتی اضافه داشته باشند.
7. **گزارش:** لینک PR، نتیجه آزمون، SHA و وضعیت انتشار به درخواست‌کننده برگردانده شود.

## اسرار لازم برای اتصال
- یک GitHub fine-grained token یا GitHub App installation با حداقل مجوزهای لازم برای branch/PR و trigger کردن workflow؛ بهتر است دسترسی به همین مخزن محدود باشد.
- یک secret تصادفی قوی برای اعتبارسنجی ورودی webhook/Action.
- در صورت استفاده از عامل توسعه مبتنی بر مدل، کلید API همان سرویس به‌عنوان secret سمت سرور.
- همه موارد باید از GitHub Actions Secrets یا Supabase Function Secrets تنظیم شوند؛ هرگز در چت، فایل HTML/JS عمومی یا commit قرار نگیرند.

## چرا این فایل به‌تنهایی اتصال را فعال نمی‌کند؟
این مخزن و اتصال Supabase نمی‌توانند خودشان به پیام‌های جاری ChatGPT گوش دهند. اتصال نیازمند تنظیم Action در محیط ChatGPT/واسط بیرونی و ثبت secrets در تنظیمات سرویس است. ابزارهای در دسترس برای این تغییر، امکان خواندن/نوشتن secrets مخزن را فراهم نمی‌کنند؛ بنابراین نمی‌توانم به‌صورت امن آن‌ها را از اینجا تنظیم کنم یا ادعا کنم webhook فعال است.

## خط قرمزهای امنیتی
- هرگز RLS، احراز هویت یا محدودیت نقش‌ها را برای آسان شدن اتوماسیون غیرفعال نکنید.
- از `service_role` در کلاینت یا توکن دارای دسترسی سازمانی/حسابی گسترده استفاده نکنید.
- هیچ فرایند خودکاری نباید بدون محدودیت روی شاخه `main` یا داده‌های production بنویسد.
- تغییرات دیتابیس ابتدا باید روی محیط آزمایشی/branch بررسی شوند و داده‌های واقعی بدون مجوز صریح تغییر نکنند.
