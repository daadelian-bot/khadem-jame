# پشتیبان‌گیری و انتقال پایگاه داده سامانه جامع مدیریت خادمین

## وضعیت و هدف
پروژه فعلاً از Supabase/PostgreSQL استفاده می‌کند. هدف این راهنما، داشتن خروجی قابل انتقال و فرایند بازیابی کنترل‌شده است؛ نه تغییر یا حذف پایگاه داده فعلی.

**هشدار:** تا وقتی یک نسخه پشتیبان از خود داده‌ها ساخته نشده و بازیابی آن روی یک پایگاه داده آزمایشی با موفقیت بررسی نشده، نباید آن را «پشتیبان قابل‌بازیابیِ تأییدشده» دانست.

## ۱. مواردی که باید پشتیبان شوند
- ساختار PostgreSQL: جدول‌ها، کلیدها، قیدها، ایندکس‌ها، viewها، توابع، triggerها و سیاست‌های RLS.
- داده‌های جدول‌ها: خادمین، سوابق خدمت، جلسات و حضور، امور مالی، تجهیزات، تنظیمات، نقش‌ها و مجوزها.
- حساب‌های احراز هویت و پیوندهای مرتبط؛ پوشش دقیق schemaهای Supabase را در خروجی dump بررسی کنید.
- فایل‌های Storage: عکس خدام و هر پیوست؛ خروجی SQL به‌تنهایی محتوای فایل‌ها را پشتیبان نمی‌گیرد.
- تنظیمات Auth، ارائه‌دهندگان ورود، SMTP، URLهای بازگشت، secrets، Edge Functions و تنظیمات میزبانی.
- نسخه کد و فایل‌های migration پروژه.

## ۲. تهیه نسخه پشتیبان محلی
نیاز است روی رایانه‌ای که به آن دسترسی دارید Supabase CLI، Docker و ابزارهای لازم نصب باشند. اتصال پایگاه داده را از Dashboard بخش Connect دریافت کنید و آن را فقط در محیط محلی امن وارد کنید؛ هرگز آن را در کد، GitHub، پیام عمومی یا APK قرار ندهید.

در محیط Bash:
```bash
export DATABASE_URL='postgresql://...'
export SUPABASE_PROJECT_REF='fxxtyfurdzpzfvweoppo'
bash scripts/backup-supabase.sh
```

اسکریپت سه فایل SQL شامل نقش‌ها، ساختار و داده‌ها می‌سازد، سپس checksum ثبت می‌کند. پوشه خروجی را در مخزن کد commit نکنید. به‌دلیل وجود اطلاعات شخصی و مالی، خروجی را در محل رمزگذاری‌شده و جدا از دستگاه اصلی نگه دارید.

بررسی سلامت فایل‌ها:
```bash
cd backups/khadem-supabase-<timestamp>
sha256sum -c SHA256SUMS
```

## ۳. بازیابی آزمایشی
1. یک پایگاه داده مقصدِ جدا و خالی، با نسخه PostgreSQL سازگار آماده کنید.
2. ابتدا از مقصد هم پشتیبان بگیرید؛ اسکریپت بازیابی را روی پایگاه داده اصلی اجرا نکنید.
3. با رشته اتصال مقصد، بازیابی را اجرا کنید:
```bash
export RESTORE_DATABASE_URL='postgresql://...'
bash scripts/restore-supabase.sh backups/khadem-supabase-<timestamp>
```
4. در صورت خطا متوقف شوید و خطا را بررسی کنید؛ برنامه را به مقصد متصل نکنید.
5. تعداد ردیف‌های جدول‌های اصلی، کلیدهای خارجی، توابع، triggerها و RLS را با مبدأ مقایسه کنید. ورود آزمایشی و مجوزهای مدیر/کاربر را نیز بررسی کنید.
6. Storage، تنظیمات Auth و Edge Functions باید جداگانه بازیابی و آزمایش شوند.

## ۴. فایل‌ها و عکس‌های Storage
فایل‌های عکس در Storage با مسیر یا URL در جدول‌ها ارجاع داده می‌شوند؛ کپی دیتابیس به‌تنهایی خود فایل‌ها را منتقل نمی‌کند. فهرست bucketها، تنظیمات public/private، سیاست‌های Storage و همه objectها را جداگانه صادر کنید. پس از انتقال، مسیرها را حفظ یا mapping آن‌ها را کنترل کنید و چند عکس را در برنامه باز کنید. کلید service role را در مرورگر یا APK استفاده نکنید.

## ۵. آماده‌سازی انتقال در آینده
- تغییرات ساختار فقط از طریق migrationهای شماره‌دار و بازبینی‌شده در `supabase/migrations/` اعمال شوند.
- هر تغییر schema باید همراه فایل migration در Git ثبت شود؛ از تغییرات دستیِ بدون migration پرهیز کنید.
- URL پروژه و کلید عمومی را از کدهای پراکنده خارج کرده و در یک تنظیمات محیطی واحد برای وب و اندروید نگه دارید. کلیدهای خصوصی فقط در محیط امن سرور باشند.
- به UUIDهای اصلی، کد خادم، کلیدهای خارجی و مسیرهای عکس در زمان انتقال دست نزنید مگر با طرح مهاجرت و آزمون.
- انتقال را ابتدا روی پروژه مقصد آزمایشی انجام دهید؛ پس از تطبیق تعداد داده‌ها، ورود کاربران، مجوزها، عکس‌ها و گزارش‌های مالی، برنامه را با تغییر تنظیمات به مقصد وصل کنید.
- کلیدهای JWT و API مقصد ممکن است متفاوت باشند؛ کاربران احتمالاً باید دوباره وارد شوند و تنظیمات ورود/ایمیل باید مجدداً پیکربندی شوند.
- برای بازیابی کامل پروژه، کد Edge Functions، secrets و تنظیمات احراز هویت را جداگانه و امن نگهداری کنید.

## ۶. چک‌لیست تأیید بازیابی
- [ ] فایل‌های SQL موجود و checksum معتبر است.
- [ ] بازیابی روی مقصد خالی بدون خطا پایان یافته است.
- [ ] تعداد خادمین و سوابق خدمت با مبدأ برابر است.
- [ ] داده‌های جلسات، حضور، مالی، پرداخت‌ها و تنظیمات بررسی شده‌اند.
- [ ] کلیدهای خارجی و قیود بدون خطا هستند.
- [ ] RLS و سیاست‌های مجوزها بررسی شده‌اند.
- [ ] ورود کاربر و نقش‌های مدیر/مسئول آزمایش شده‌اند.
- [ ] عکس‌ها و فایل‌های Storage باز می‌شوند.
- [ ] Edge Functions و تنظیمات Auth/SMTP بررسی شده‌اند.
- [ ] برنامه به مقصد آزمایشی وصل شده و سناریوهای اصلی تست شده‌اند.
