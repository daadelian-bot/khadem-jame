# Database migrations

این پوشه منبع کنترل‌شده تغییرات ساختار پایگاه داده است. فایل‌های migration باید به ترتیب زمانی نام‌گذاری شوند و همراه کد برنامه بازبینی شوند.

## ثبت ساختار فعلی به‌عنوان baseline
روی رایانه‌ای با Supabase CLI نصب‌شده، ابتدا به پروژه فعلی متصل شوید:
```bash
supabase login
supabase link --project-ref fxxtyfurdzpzfvweoppo
supabase db pull initial_schema_snapshot
```
فرمان آخر ساختار موجود را از پروژه می‌خواند و یک migration محلی تولید می‌کند. فایل تولیدشده را بازبینی کنید و فقط پس از اطمینان از اینکه secrets یا داده‌های واقعی در آن نیستند، آن را در این پوشه commit کنید. این فرمان به‌خودی‌خود داده‌های جدول‌ها را در migration قرار نمی‌دهد.

## قوانین
- برای هر تغییر ساختاری یک migration جدید بسازید؛ migration اعمال‌شده را ویرایش نکنید.
- تغییرات را ابتدا روی پروژه آزمایشی اعمال و بررسی کنید.
- پیش از تغییرات مهم از داده‌ها نسخه پشتیبان بگیرید.
- اطلاعات واقعی، رشته اتصال، کلید service role، JWT secret و فایل‌های dump را هرگز در Git ثبت نکنید.
- migrationها به‌تنهایی جایگزین نسخه پشتیبان داده‌ها، فایل‌های Storage یا تنظیمات Auth نیستند.
