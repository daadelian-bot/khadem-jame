# گزارش بازسازی ساختار پایگاه داده

شاخه آماده‌سازی: `rebuild/schema-migrations-20261013`

## فایل‌های ثبت‌شده
- `supabase/migrations/20261013000000_rebuild_schema_baseline.sql` — تصویر بازسازی‌شدنی از ساختار زنده پروژه `khadem-jame-next` در ۲۰۲۶-۱۰-۱۳؛ شامل جدول‌ها، قیود، ایندکس‌ها، توابع، تریگرها، RLS، سیاست‌ها و مجوزهای جدول.
- `supabase/migrations/20261013010000_v141_index_compatibility_columns_for_vehicles_and_chat.sql` — ستون‌های سازگاری مورد نیاز فایل index نسخه ۱۴۱ برای خودروها و پیام‌ها.
- `supabase/migrations/20261013020000_v141_add_missing_application_module_tables.sql` — جدول‌های جاافتاده برای حضور و غیاب، نقش‌ها و مجوزها، مأموریت‌ها، صندوق، نیکوکاران، فیلدهای پویا، ثبت رخدادها و درخواست بازیابی رمز.

## وضعیت و محدودیت‌ها
- مهاجرت سازگاری خودرو/پیام و مهاجرت جدول‌های جاافتاده روی پروژه جدید `khadem-jame-next` اعمال شده‌اند.
- فایل baseline برای بازسازی یک پروژه خالی است؛ آن را کورکورانه روی پروژه‌ای با ساختار متفاوت اجرا نکنید. این فایل داده کاربران یا ردیف‌های جدول‌ها را کپی نمی‌کند.
- پروژه قدیمی `khadem-jame` و داده‌های واقعی آن دست‌نخورده مانده‌اند.
- RLS روی جدول‌های عمومی فعال است. هیچ سیاستی برای آزادسازی اطلاعات مالی یا هویتی به نقش `anon` اضافه نشده است.
- این سه فایل جایگزین بازیابی متن دقیق مهاجرت‌های قدیمی نیستند؛ baseline از ساختار واقعی فعلی ساخته شده تا بتوان یک پایگاه تازه را بازسازی کرد.
- فایل `index.html` سایت هنوز در GitHub Pages منتشر/جایگزین نشده است. نسخه آزمایشی بازشدن بدون صفحه ورود جداگانه آماده شده و در آن هشدار داده شده که حذف صفحه ورود، مجوز Supabase را تغییر نمی‌دهد.
- پیش از اتصال نسخه سایت به داده‌های واقعی، باید سیاست‌های RLS برای مدل دسترسی نهایی، ستون‌های مورد انتظار کلاینت و عملیات هر ماژول یکپارچه و آزمون شوند.
